## 2. 实现前必须补齐

| 缺口 | 必须形成的规则 | 最低验收 |
|---|---|---|
| 身份和跨会话授权 | 分开逻辑任务、Plan 版本、分支、worktree、协调会话与 provider 会话；追加交接记录，不修改旧 Plan 创建者。验收记录使用实际接管者身份，并绑定有效授权链。 | A 交接给 B 后，B 可按权限继续；A 的迟到提交/合并/清理被拒绝；两个 B 竞争只能有一个成功。 |
| 接管与在途操作 | 递增的执行代次必须在采纳结果和实际变更前复核。仅租约超时不能证明旧进程退出或授权转移；正常交接、旧会话失联恢复、旧 Worker 继续运行必须有各自规则。 | 不因主会话切换而重复启动 Worker；原 Worker 可受新协调者监督；旧代次不能发布状态或推进 refs。 |
| 提交、合并、目录状态 | 至少分开成果状态、目标集成状态、工作区状态。`已提交 + 待合并 + 目录已回收` 必须是合法组合；各操作独立记账与幂等恢复。 | 在提交成功、引用更新、目录删除及登记更新之间分别注入崩溃，恢复不重复提交、不误报已合并。 |
| 已检出分支的更新 | 更新前检查目标 ref 的预期 OID 与所有相关 worktree；不能直接推进已检出分支使其 HEAD、index、文件失配。目标目录脏或有覆盖冲突时保持待合并。 | 目标已检出且带 staged/unstaged 修改时，refs、文件和暂存状态不变；目标竞争推进时原子拒绝。 |
| 精确验收与合并候选 | 证据绑定 contract、base、patch、候选 tree 和 reviewer。沿用现有前后校验，扩展到任务分支提交与集成；hooks 改写后不得把新树当作原已验收成果。 | Review 后改字节、hook 改树、目标前进、合同变更均拒绝复用旧凭据；历史验收记录保留。 |
| 回收后的恢复证明 | 回收前建立受管持久引用，记录 commit/tree/base 与必要制品清单；未跟踪/忽略独有内容明确归档或继续保留目录。普通分支删除不等于证据引用删除。 | 回收待合并成果和 WIP 后，在隔离测试仓库执行 GC，再重建并核对树、暂存/工作区差异及归档摘要。 |
| 排队期间环境漂移 | 区分运行中 Worker 的固定基线与尚未分配任务的候选基线。承接需符合用户政策、目标历史、已验证交付链、保留文件内容/索引及路径冲突条件；未知变化阻塞并返回精简差异。 | 已验证无交叉交付可按政策承接；新增未知路径、暂存变化、重叠、分支切换与未经记录推进均阻止自动承接。 |
| 配额与锁 | 给出任务/工作区/物理仓库/项目族锁的顺序和持有范围。模型审查、排队不能占全局锁；共享目录变更和 hooks 需有明确排他保证。满额时通过先固化、释放并重建等受控路径让集成继续。 | 两个外部目录占槽、唯一剩余槽需要从 Work 转入集成时可推进；不超总额、不删除未知目录、取消可恢复。 |
| 旧版本与发布 | 旧任务缺新字段时采取附加记录或兼容读取；无法证明归属的分支禁止自动删除。保留模型路由、Git 策略、证据和观察者账本。CI 使用受控 CLI/SQLite fixture。 | 0.8.2 在途/失败/待清理任务可读可恢复；独立 consumer 能得知终态；Windows/Linux CI 通过才发布。 |

## 3. 外部意见的取舍

采纳其指出的已检出分支安全、原子引用更新、跨会话执行代次、可恢复证明、排队基线规则、配额进展与发布门禁。

以下建议需要调整，不能直接照搬：

- 外部报告将若干设计遗漏标为 P0。这是条件性风险推演，不是已证实的数据丢失漏洞；列为实现与发布阻塞条件，并由针对性测试确认。
- 0.8.2 已有受管交付/快照引用、patch/contract 校验、hooks 后检查、部分 readiness 承接和通知账本。应扩展这些机制，不能把它们描述为完全缺失，或重新建立另一套相同系统。
- 外部建议的 finalize 子状态仍是线性序列，不能完整表达“目录先回收、稍后合并”。采用独立状态维度，并定义允许的组合。
- 不能只靠 TTL 过期自动夺权；需要实际授权、在途操作核对和变更前代次检查。保留旧 Worker 输出作为证据，与允许旧协调者写状态是不同权限。
- 原地将 Worker 目录改为集成目录不是必选方案。若采用，必须结束原写入租约、固化结果、建立新集成契约并禁止旧 provider 继续写；否则先安全释放再重建更清晰。
- 不强制修改用户全局 Git/操作系统长路径设置。按命令能力采用有界参数、stdin/文件输入或完整索引筛选；不是所有 Git 命令都支持同一 pathspec 参数。
- Windows 删除失败进入可重试待清理状态，不能抹掉已提交/已合并事实；目录或残留仍占配额，直到实际核验释放。
- 不按任务重新创建通知总线；继续扩展现有事件账本和 `wait-for-job`，把任务/作业关系及交接消费者规则写清楚。

## 4. 建议修订后的三阶段顺序

CI fixture 修复与远端发布门禁作为贯穿三阶段的前置工作，不能拖到发布后。

1. **身份、交接与分支绑定**：实体/字段契约，兼容迁移，单写入者和执行代次，正常交接与失联恢复，推荐选项，任务分支/目标/基线绑定，精简状态与可审计授权记录。
2. **交付、集成与恢复**：精确验收，任务分支提交，已检出目标安全合并，独立状态与操作日志，持久 refs 和重建证明，排队后的基线检查、结构化漂移及受限承接。
3. **调度、回收与完整验证**：集成可用槽位与进展，目录残留和安全退休，条件满足后的分支清理，Auditor 最低状态展示，真实跨会话/并行/崩溃流程及双平台 CI。

可延后：自动解决合并冲突、自动 rebase、跨物理仓库直接合并、多机器协调租约、复杂可视化和高级调度优化。冲突保留并显式处理、精简的 CLI/JSON/Auditor 展示足以支撑首版闭环。

## 5. 发布前最低闭环

- 原会话正常移交；旧会话失联；两会话竞争认领；交接后旧会话恢复。
- Worker 运行、待审查、已验收待提交、已提交待合并、已合并待清理等阶段分别接续。
- 脏目标、目标被外部 worktree 检出、目标推进、hooks 改树与合并冲突。
- 待合并成果和拒绝/未验收 WIP 回收后可重建；唯一忽略制品不能遗漏。
- 目标有交付推进/未知修改两类漂移；已分配 Worker 基线不重写。
- 配额满额时从 Work 到集成可推进；进程/句柄占用和幽灵登记恢复不误释放。
- 同一步骤重复调用、崩溃恢复、通知重订阅均幂等；旧版本记录和模型路由保留。
- Windows/Linux 确定性 CI 全绿；真实 provider 和跨会话验收与代码测试分开记录。
