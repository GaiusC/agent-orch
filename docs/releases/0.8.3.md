# Agent Orch 0.8.3

0.8.3 将分支、提交、合并和目录回收做成运行时约束，并修复旧 native Plan
缺少 repository_identity 时无法 Accept 的问题。它包含 Auditor、插件和 skill 更新。

## 三阶段实现

1. **身份、交接、分支**：不可变 Plan 与可转移任务 authority 分离。
   `task-handoff` 显式 prepare/claim/recover，追加 owner/epoch 历史，拒绝旧会话变更。
   在途 Worker 可被接管，保留原 provider session、基线和证据。新任务先选择或
   按已批准政策绑定分支；复用前任分支必须具名、完成子任务并释放目录。
2. **交付、集成、恢复**：任务分支精确提交通过正常 Git hooks，保护 ref 和
   commit/tree/patch/acceptance/evidence 证明后即可回收 worktree，保持待合并。
   目标被其他目录检出、工作目录脏或忽略文件冲突时不推进 refs。目标前进后
   使用新集成 Plan 和新 Review/Accept。提交和引用更新中断可从 journal 恢复。
   仅可证明的交付链承接已批准基线；未知修改返回精简漂移证据并要求重新审查。
3. **调度、回收、验证**：默认 Worker 上限 3、总辅助工作区上限 5；纳入外部
   worktree 与已登记协调副本，并在容量允许时保留集成槽。未合并成果可先固化、
   释放再集成。独有忽略制品阻止回收，分支删除只针对已合并且无引用的受管分支。
   Auditor 分开展示交付、目标集成、目录状态及任务归属，待合并提交不冒充目标交付。

## 兼容与授权

- 保留现有模型路由、Git 政策、旧 Plan、失败 Review 收据和 observer ledger。
- 旧合同缺少仓库身份时，必须验证原生 Plan 项目/common directory、合同摘要、
  记录的 Work 来源及实际 worktree 祖先，再生成新 Review 的附加 provenance。
  不修改历史收据，也不为无法验证的任务生成快捷验收。
- `ask` 仍要求具体提交批准；显式推荐 Git 政策才启用新任务自动分支和精确本地
  auto commit。合并默认单独询问，push、发布和历史重写均无默认授权。
- 在途旧 runtime 必须先接上新版再交接；打开的聊天不自动更新 MCP 工具目录。
- 手工已有 commit 的记录保留 legacy/current-branch 兼容路径。新任务分支使用
  coordinator 负责的正常提交，冲突与人工 Git 操作由明确流程处理。
- 不实现自动 rebase、自动冲突解决、跨独立物理仓库合并或多机器租约夺权。

## 验证

确定性回归覆盖交接竞争和旧主会话隔离、模型变更批准、原生 Plan 字节不变、
精确提交和中断恢复、脏目标与忽略冲突、受保护成果 GC 后重建、未知漂移阻塞、
分支复用与安全删除、容量保留、独立 observer 和 Auditor 状态。

真实 CLI 测试只操作新建合成临时项目：两个 Codex Worker 并行，MCP 客户端
模拟多个协调身份并在途中交接，AGY 分别 Review，再释放待合并成果、生成新集成、
重新 Review/Accept、提交、合并和清理。另测 CC CLI 执行与原 session 续写和 AGY
审查。模拟协调身份与真实 provider 调用分别记录，不声称创建了多个桌面聊天。

CI 去掉已安装 provider CLI 和用户 SQLite 数据库依赖，Windows/Linux 分别覆盖
Node 18/20/22 和 Python 3.10/3.11/3.12。候选与正式发布均以精确 commit 为准，
本地完整证据和配置保留核对收据存放在被 Git 忽略的 releases 目录。
